# Разработка и запуск

## Требования

Node.js 22.12+ для ветки 22 или совместимая поддерживаемая версия 24+, pnpm 10.34.5, Docker с работающим движком. Версии пакетов фиксируются pnpm-lock.yaml.

## Подготовка

1. `pnpm install --frozen-lockfile` из корня.
2. Скопировать `.env.example` в `.env`. Заполнить OPENAI_API_KEY локально, не через чат и не в Git. Без ключа генерация завершается ошибкой конфигурации, а не фиктивным ответом.
3. `docker compose up -d postgres`. PostgreSQL доступен только через localhost:5432; данные сохраняются в Docker volume.
4. `pnpm db:migrate`. Миграции идемпотентны и дополнительно выполняются при старте API.

Пароль в Compose и шаблоне — только локальный пример, не production-секрет. Если задан POSTGRES_PASSWORD, DATABASE_URL должен содержать согласованное значение. Не менять пароль существующего volume только переменной окружения: для существующей БД он не обновляется автоматически.

## Режим разработки

`pnpm dev` запускает API и frontend. Эта команда выполняется пользователем, а не автоматически при подготовке проекта.

Frontend: http://localhost:5173. API: http://127.0.0.1:3001 при значениях .env.example. Vite проксирует /api. APP_ORIGIN=http://localhost:5173; не смешивать localhost и 127.0.0.1 в браузере, если разрешен только один origin.

## Production-сборка

1. `pnpm build`.
2. Настроить DATABASE_URL, OPENAI_API_KEY, OPENAI_MODEL=gpt-5.6-terra, NODE_ENV=production, APP_ORIGIN с точным публичным HTTPS-origin, HOST и PORT.
3. `pnpm start` запускает собранный Fastify и раздает apps/web/dist с того же origin.

Перед публичным размещением нужен HTTPS reverse proxy. Cookie в production имеет Secure и не подходит для обычного localhost HTTP. Если reverse proxy буферизует ответы, отключить buffering для потокового маршрута. API выставляет X-Accel-Buffering: no, но настройки прокси должны это учитывать.

GET /api/health проверяет соединение с БД. NODE_ENV, APP_ORIGIN и ключ — серверные настройки; переменные VITE_* с ключами не создавать.

## Проверки

- `pnpm check`: lint, строгие типы, unit-тесты и сборка.
- `pnpm format:check`: форматирование.
- `pnpm audit --prod`: известные проблемы production-зависимостей.
- TEST_DATABASE_URL для PostgreSQL integration и E2E — см. testing.md.

E2E использует временный listener на случайном порту и закрывает его; не оставляет dev/preview-сервер. Тестовый провайдер существует только в тестах.

## Сроки и очистка

Рабочие предположения: 1 час от создания сессии и 6 часов от создания каждого сообщения. Проверка доступа выполняется немедленно; физическая очистка — раз в минуту ограниченными пакетами. Резервные копии и данные у провайдера не подпадают автоматически под этот локальный таймер — их политика настраивается отдельно при эксплуатации.

SIGINT/SIGTERM останавливают активные генерации и закрывают сервер/пул. PostgreSQL volume сохраняется после docker compose down; команду удаления volume не использовать без намерения удалить данные.
