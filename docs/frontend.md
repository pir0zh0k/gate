# Frontend: `apps/web`

React 19 + TypeScript + Vite 7 + Tailwind 4. Интерфейс `gate`, модель в шапке — `GPT-5.6 Terra`. Один анонимный диалог, без аккаунтов, вложений, выбора модели и списка чатов. Новая сессия доступна только после истечения старой; кнопка повторного подключения сохраняет действующую серверную cookie.

## FSD и границы

- `app/` — точка входа, StrictMode, дизайн-токены и адаптивные стили. Tailwind подключает preflight и системный шрифтовой токен; стили конкретных компонентов находятся в одном stylesheet. Нет внешних шрифтов или CDN.
- `pages/chat/ChatPage.tsx` — компоновка страницы, приветствие, рабочие подсказки, панель, светлая/тёмная тема и прокрутка.
- `pages/chat/useChat.ts` — жизненный цикл анонимного диалога: авторизация, история, отправка, отмена, синхронизация и курсорная пагинация.
- `features/send-message/Composer.tsx` — контролируемое растущее поле ввода и реальные действия отправки/остановки.
- `entities/message/MessageView.tsx` — сообщения пользователя и безопасный Markdown ответа, подписи прерванных/ошибочных ответов.
- `shared/api/` — same-origin HTTP-клиент и валидируемый NDJSON-поток.
- `shared/lib/cache.ts` — версионированный, привязанный к сессии кеш.
- `shared/ui/CopyButton.tsx` — общий механизм копирования ответа и кода с обратной связью.

Импорты направлены сверху вниз. Схемы, типы, лимит ввода и сроки жизни берутся из `@gate/contracts`; непроверенные ответы API принимаются как `unknown`. В UI нет `any`, provider SDK или секретов.

## Состояния и протокол

1. `POST /api/session` подтверждает серверную cookie. До ответа никакой локальный текст истории не отображается.
2. Только после подтверждения публичного ID можно показать валидный кеш этой сессии. `GET /api/messages` затем заменяет предварительную историю серверными данными. Пока проверка истории не завершилась, ввод отключён. При сбое доступна повторная попытка подключения.
3. Пустой экран показывает «С чего начнём?» и три подсказки. Нажатие действительно заполняет поле и переводит в него фокус, но не отправляет запрос без согласия пользователя.
4. Отправка добавляет одно оптимистическое сообщение с валидным UUID и делает `POST /api/messages/stream` с `{content, requestId}`. Текст очищается только после `start`; черновик, отредактированный во время ожидания, не стирается. Повтор того же текста после неоднозначного сетевого сбоя сохраняет `requestId`, чтобы сервер мог применить идемпотентность.
5. `start` создаёт один ответ; `delta` дописывает его, `done`/`error` завершают поток. Декодер сохраняет UTF-8-состояние и остаток строки между пакетами, обрабатывает последнюю строку без перевода строки. Проверяются схемы, порядок событий и ID ответа. EOF без терминального события, повреждённый JSON/UTF-8 и чрезмерно большое событие считаются обрывом.
6. «Остановить ответ» отменяет fetch через `AbortController`. Частичный текст остаётся, а серверная история перечитывается после любого завершения. Оптимистический пользовательский дубль удаляется. Если отмена опередила сохранение на сервере и история ещё имеет `generating`, локальный частичный текст не заменяется пустым снимком. Следующая синхронизация принимает окончательный серверный статус.
7. «Обновить историю» при ошибке повторяет серверную синхронизацию без сброса диалога. «Показать предыдущие сообщения» использует `nextCursor`, объединяет по ID и сохраняет хронологический порядок.
8. При `SESSION_EXPIRED`, несоответствии сессии или достижении фиксированного часа поток и запросы отменяются, история, черновик и кеш удаляются; старая переписка недоступна. Показывается отдельное объяснение и действие «Начать новый диалог». Срок контролируется по серверному времени с поправкой часов клиента, включая возвращение вкладки в фокус.

Все fetch используют `credentials: 'same-origin'`. Vite проксирует `/api` на `http://127.0.0.1:3001`; production должен обслуживать frontend и `/api` с одного origin. Обновление статуса локального ответа не является доказательством его сохранения в БД: источник истины — API истории.

## Кеш и приватность

Ключ `gate.history.v1`: `{version: 1, session, messages}`. Здесь только публичный ID, временные метки и сообщения; токен HttpOnly cookie не читается и не записывается. Кеш другой/истёкшей сессии, неизвестная версия и повреждённые данные очищаются. Просроченные сообщения исключаются по `expiresAt` (6 часов от создания), а сохранённый `generating` отображается как прерванный локальный снимок, не как активный поток. Запрет localStorage, исчерпание квоты и повреждённый JSON не ломают приложение. Предпочтение темы хранится отдельно в `gate.theme`; черновик на диск не записывается.

Кеш — текст в браузере, не зашифрованное хранилище. Истечение часа лишает клиента доступа независимо от шестичасового срока хранения сообщений на сервере.

## Доступность и Markdown

- Enter отправляет, Shift+Enter добавляет строку; IME-composition и keyCode 229 не вызывают отправку. Пустой ввод и ввод до готовности сессии не отправляются. Максимум — `MAX_INPUT_LENGTH` (16 000 символов).
- Поле растёт до 200px, затем прокручивается. Кнопки имеют русские доступные названия, видимый клавиатурный фокус и настоящие обработчики.
- Единственный `role="status"`/`aria-live="polite"` сообщает изменения этапов и ошибки, но не каждый токен. Сообщения не являются live region. Иконки и индикатор потока скрыты от accessibility tree.
- Автопрокрутка происходит только у конца истории; при чтении выше есть рабочая кнопка вниз. При подгрузке старой страницы компенсируется изменение высоты.
- Адаптивный экран использует `100dvh`, учитывает safe-area и скрывает широкую панель на мобильном. Светлая тема по умолчанию, тёмная — настоящий переключатель. Анимация отключается при `prefers-reduced-motion`.
- `react-markdown` + `remark-gfm`, `skipHtml`, без `rehype-raw`. Ссылки ограничены безопасными URL и имеют `noopener noreferrer`; внешние изображения не загружаются. Код и полный ответ копируются через Clipboard API; при его недоступности выводится ошибка вместо ложного успеха.

## Проверки без серверов

Из корня репозитория:

```sh
pnpm exec vitest run apps/web
pnpm exec eslint apps/web
pnpm --filter @gate/web typecheck
pnpm --filter @gate/web build
pnpm exec prettier --check apps/web docs/frontend.md
```

Тесты покрывают кеш/TTL/повреждения/storage denied, фрагментированный UTF-8 и NDJSON, ошибки/обрывы, клавиатурный ввод и IME, авторизацию и истечение сессии с рассинхронизацией часов, идемпотентный повтор, гонку отмены/сохранения, пагинацию, безопасный Markdown и копирование. DOM-тесты явно выбирают jsdom; остальные выполняются в Node. Они используют контролируемые HTTP-ответы, не заменяют реальную интеграционную проверку API/PostgreSQL/провайдера.

На Node 26 встроенный experimental localStorage может конфликтовать с jsdom и выдать предупреждение. Для чистого тестового вывода можно выполнить `NODE_OPTIONS=--no-webstorage pnpm exec vitest run apps/web`: это отключает только Node-хранилище, не browser localStorage приложения.

Production-артефакт — `apps/web/dist`. Dev/preview-серверы для этих проверок не нужны и не запускаются; визуальная проверка статического артефакта и полноценный E2E выполняются отдельно.
