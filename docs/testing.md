# Проверки

## Автоматические уровни

- `pnpm test`: общие runtime-контракты, backend-логика, frontend-кеш, NDJSON и React-поведение.
- `TEST_DATABASE_URL=… pnpm test:integration`: реальные SQL-запросы, миграции, сессии, порядок/контекст, изоляция, конкуренция и сбои. Использовать отдельную тестовую БД.
- `TEST_DATABASE_URL=… pnpm test:e2e`: production-сборка frontend + Fastify API + реальная PostgreSQL + Chromium. Сначала `pnpm build` и `pnpm exec playwright install chromium`.

E2E поднимает только временный HTTP-listener теста на случайном localhost-порту, без Vite/dev/preview-сервера. Закрывает listener после проверки. Для SQL создает отдельную схему `gate_browser_<pid>` и удаляет ее после тестов, не очищая таблицы рабочей схемы.

OpenAI в автоматических E2E заменен управляемым адаптером **только внутри файла теста**: это позволяет воспроизводить задержку, отмену и ошибку после частичного ответа. Production не имеет тестового провайдера или фиктивного fallback.

Проверяемые браузером сценарии: поток и сохранение/перезагрузка без дубликатов; HttpOnly cookie и изоляция; запрет другого origin; остановка с сохранением; частичная ошибка; истечение часа и удаление после шести часов; мобильная верстка, тема, подсказки и поврежденный localStorage.

## Реальный провайдер

Успешные автоматические тесты не доказывают доступ API-проекта к OpenAI. Для финальной проверки реальной модели нужен серверный OPENAI_API_KEY, сеть и отдельный реальный запрос. Не публиковать ключ, cookie или текст переписки в отчетах.

## Остальные проверки

`pnpm lint`, `pnpm typecheck`, `pnpm format:check`, `pnpm build`, `pnpm audit --prod`.

TTL проверяется внедренными тестовыми часами; ждать настоящий час/шесть часов не требуется. Скриншоты браузерных сценариев сохраняются в `test-results/`, эта папка не коммитится.
